Deep Dive: Surviving & Winning with GCP Spot GPUs

1. Spot Economics vs. DWS Flex

While DWS Flex-Start provides a 2-hour queue with guaranteed non-preemptible execution once granted, Spot VMs are interruptible at any moment when Google Cloud needs capacity back. In exchange, Spot delivers 60%–91% discounts, making it ideal for distributed checkpointed pretraining and resilient worker nodes.

2. Why Synchronous Round-Robin Retries Work

Spot capacity is not static: large enterprise jobs finish every few minutes, temporarily replenishing the spot pool in unpredictable zones. A round-robin probe loop cycles across 10–20 zones rapidly. Instead of waiting in a single zone, the loop will grab any capacity release immediately.

3. Checkpointing & Multi-Region GCS-FUSE

Because Spot VMs can be reclaimed with a 30-second preemption notice, state must be continuously preserved. The script mounts a Cloud Storage bucket directly to /gcs. When a preemption signal arrives, modern training loops (such as PyTorch Lightning or Megatron-LM) trigger an emergency checkpoint directly into the bucket, allowing instant resume in another zone.

Before submitting parallel sprays, the script queries limit - usage for target metrics across candidate regions. Zero-quota regions are pruned gracefully without failing the entire run.

2. Programmatic Quota Requester

Use Google's modern Cloud Quotas API (gcloud beta quotas preferences create) or the bundled ./scripts/request-gpu-quota.sh to request capacity across multiple regions in one step.

3. Future Reservations (Calendar)

For mission-critical deadlines or multi-node training, automate scheduling guaranteed hardware windows using DWS Calendar-Mode (gcloud compute future-reservations create).
